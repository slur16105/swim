# 탑뷰 프로토타입 설계 · 2026.11.01

사용자 기획서 v0.1의 첫 작업 범위를 구현한다. 서버·계정·커뮤니티 없이 단일 브라우저에서 완결되는 로컬 MVP로 제작한다.

Vite로 Phaser를 로컬 번들에 포함하고 Vanilla JS로 화면을 연결한다. CDN 방식보다 초기 설치가 필요하지만 이후 실행 시 외부 서비스 의존성이 없고 정적 배포가 가능하다. 캔버스 단독 UI 대신 Phaser와 DOM을 분리하여 모바일 폼과 접근성을 유지한다.

## 데이터와 세션

`{version:1, cap, records:[]}`를 LocalStorage에 저장한다. 기록은 `{id,date,stroke,distance,minutes,status}`이며 status는 pending 또는 complete이다. 기록 저장 성공 이후에만 연출을 시작한다. 연출이 끝나면 complete로 저장하고 완료 기록에서 총 XP를 계산한다. 저장 실패 시 UI가 성공을 표시하지 않으며 pending 상태를 보존한다. 새로고침은 pending 세션을 처음부터 재생한다. 완료 여부로 지급을 판단하므로 중복 XP가 발생하지 않는다.

25m당 10 XP, 레벨 N에서 다음 레벨까지 N×100 XP. 수정은 기존 ID를 유지하고 합계를 재계산한다. 재생은 지급 상태를 변경하지 않는다. 수정/신규 기록은 연출 중 잠금 처리한다. 여러 탭은 원본 저장 문자열을 비교하여 오래된 탭의 덮어쓰기를 막는다.

## 표현

가로 25m 수영장 5레인, 중앙 3번 레인에 캐릭터 1명. 정적 타일·로프·주변 소품과 4프레임 자유형 스프라이트를 코드로 생성한다. 25m 구간마다 방향을 뒤집으며 구간당 0.8초를 배정한다. 1×/2×/4× 및 일시정지를 제공한다. 렌더링 콜백은 기록 ID와 진행 거리만 전달하며 저장소를 직접 다루지 않는다.

레트로 감성의 크림색 배경, 초록 UI, 청록색 수면을 사용한다. PC는 게임/캐릭터 2열, 모바일은 단일 열과 2×2 통계 구성이다. 외부 이미지·웹폰트를 사용하지 않는다.

## 검증

입력 경계값, 실제 날짜, 레벨 경계, pending 제외, 기록 수정, 주간/연속일 계산, 저장 실패·중복 ID·탭 충돌을 Node 테스트로 확인한다. 브라우저에서 첫 기록, 진행, 왕복, XP 지급, 수정, 다시 보기, 새로고침 복구, 수모 저장, 작은 화면을 검증한다. 배포 빌드도 실행한다.
