# 실제 휴대폰 수용 테스트 · Story 1.7

실제 iPhone Safari와 Android Chrome에서 아래 순서로 확인하고 [결과표](mobile-device-results.md)에 기기별로 기록합니다. 현재 실기기 통과 결과는 없습니다. 브라우저 창 크기 변경과 자동 테스트 결과를 실제 기기·200% 확대·스크린리더 통과로 대신하지 않습니다.

## Mac에서 테스트 서버 실행

프로젝트 폴더에서 실행합니다. Node.js 20.19+ 또는 22.12+와 OpenSSL이 필요합니다.

```sh
npm run mobile:prepare
npm run mobile:serve
```

터미널에 표시되는 주소를 기준으로 사용합니다. 현재 LAN 주소의 예시는 다음과 같습니다.

- 인증서 설치 안내: [http://172.30.74.82:8080](http://172.30.74.82:8080)
- 실제 앱: [https://172.30.74.82:8443](https://172.30.74.82:8443)
- 환경 진단: [https://172.30.74.82:8443/test-environment](https://172.30.74.82:8443/test-environment)

HTTP 8080은 공개 CA 인증서 다운로드와 설치 안내 전용입니다. 수영 앱의 생성·저장 검증은 인증서 신뢰 설정 후 HTTPS 8443에서 수행합니다. LAN HTTP 앱 주소나 인증서 경고를 무시한 상태에서 저장 검증을 진행하지 않습니다. 앱의 secure-context/Web Locks 보호 검사를 해제하지 않습니다. Web Locks는 HTTPS 보안 컨텍스트를 요구합니다. [MDN Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)

Mac과 휴대폰을 같은 Wi-Fi에 연결하고 테스트 동안 Mac을 켜 둡니다. Mac이 잠들거나 터미널 서버가 종료되면 접속할 수 없습니다. 게스트 Wi-Fi의 기기 격리, VPN, 방화벽 때문에 같은 Wi-Fi에서도 연결이 막힐 수 있습니다. Mac의 LAN 주소가 달라지면 두 명령에 새 주소를 전달합니다. 예: `npm run mobile:prepare -- --host <새 IPv4>` 후 `npm run mobile:serve -- --host <새 IPv4>`. 포트를 바꿀 때도 두 명령에 같은 `--https-port`와 `--http-port`를 전달합니다. CA 유효기간은 7일이며 만료되거나 IP가 바뀌어 새 CA가 생성되면 휴대폰에서도 새 인증서를 설치·신뢰해야 합니다. HTTPS 호스트/포트가 바뀌면 별도 저장 공간이므로 기존 테스트 기록이 나타나지 않을 수 있습니다.

인증서·키는 `.local/mobile-test`에 생성되며 이 디렉터리는 웹에 제공하지 않습니다. Mac 시스템 신뢰 저장소에는 자동 설치하지 않습니다. 이 서버는 로컬 Wi-Fi 테스트용이며 공개 터널·공개 배포를 만들지 않습니다.

## 휴대폰에서 인증서 설치

설치할 인증서는 이 프로젝트의 테스트용 CA입니다. 서버 안내에 나온 이름과 다운로드한 인증서를 확인합니다. 개인 키를 휴대폰에 복사하지 않습니다.

### iPhone / iPad

1. Safari로 HTTP 8080 안내 주소를 열고 CA 인증서(`/ca.cer`)를 다운로드합니다.
2. 설정의 다운로드한 프로파일에서 설치합니다. 해당 항목이 보이지 않으면 설정 → 일반 → VPN 및 기기 관리에서 다운로드한 프로파일을 찾습니다. 메뉴명은 OS 버전·언어에 따라 다를 수 있습니다.
3. 설치 후 설정 → 일반 → 정보 → 인증서 신뢰 설정에서 해당 테스트 CA의 **루트 인증서에 대한 전체 신뢰**를 켭니다. 프로파일 설치만으로 HTTPS 신뢰 설정이 완료되지 않을 수 있습니다. [Apple의 수동 인증서 신뢰 안내](https://support.apple.com/en-ie/102390)
4. Safari에서 HTTPS 8443 앱 주소와 `/test-environment`를 엽니다. 인증서 경고가 남으면 테스트를 멈추고 주소·CA 설치·전체 신뢰를 확인합니다.

### Android

1. Chrome에서 HTTP 8080 안내 주소로 접속해 CA 인증서를 다운로드합니다.
2. 기기의 설정 검색에서 `CA 인증서` 또는 `인증서 설치`를 찾아 사용자 CA로 설치합니다. 보안/개인정보 보호/암호화 및 사용자 인증 정보 등의 메뉴에 있을 수 있으며 제조사·OS별 경로가 다릅니다. Wi-Fi 전용 인증서와 CA 설치를 구분하고 기기 안내를 따릅니다.
3. 기기가 화면 잠금이나 설치 확인을 요구하면 내용을 확인합니다. 회사 관리 기기에서 설치가 막히면 정책을 우회하지 않고 결과표에 차단 사유를 적습니다.
4. Chrome에서 HTTPS 8443와 `/test-environment`를 엽니다. 사용자 CA가 해당 브라우저에서 신뢰되지 않거나 경고가 남으면 통과로 기록하지 않습니다.

테스트가 끝나면 설치한 이름을 확인해 iOS의 해당 프로파일/인증서, Android의 해당 사용자 CA를 제거합니다. 다른 인증서를 삭제하지 않습니다. Mac 서버는 실행 터미널에서 Ctrl+C로 종료합니다.

## 시작 전 확인

- 결과표에 시각, 기기명, OS·브라우저 정확한 버전, HTTPS 주소, 가로/세로 방향과 확대·보조기술 설정을 적습니다.
- `/test-environment`의 secure context, Web Locks, dialog, 저장소 진단 결과를 기록합니다. 지원 실패가 있으면 보호 안내를 캡처하고 생성·저장 통과로 표시하지 않습니다.
- 테스트 전용 브라우저 저장 공간을 사용합니다. 기존 기록이 있으면 삭제하지 말고 담당자와 분리 방법을 정합니다. 일반/시크릿 창 간 저장 유지 차이도 기록합니다.
- 같은 테스트에서는 `https://172.30.74.82:8443`처럼 **프로토콜·호스트·포트를 고정**합니다. 데이터는 해당 기기·브라우저·origin의 LocalStorage에만 저장됩니다. Mac과 휴대폰, Safari와 Chrome 사이에 동기화되지 않습니다. 브라우저 데이터 삭제로 기록이 사라질 수 있습니다.

## 막혔을 때

- HTTP 안내도 열리지 않음: 같은 Wi-Fi, 현재 LAN 주소, Mac 절전·서버 종료, 게스트 격리·VPN·방화벽을 확인합니다.
- HTTP 안내는 열리지만 HTTPS 경고: CA 설치와 iOS 전체 신뢰, 주소 변경·인증서 재생성을 확인합니다. 경고를 건너뛰어 판정하지 않습니다.
- HTTPS는 열리지만 읽기 전용: `/test-environment` 결과와 브라우저 버전을 기록합니다. 지원되는 최신 브라우저에서 다시 확인하되 guard를 제거하지 않습니다.
- 데이터가 사라져 보임: 원래 기기·브라우저·일반/시크릿 모드와 정확한 origin으로 돌아갑니다. 다른 주소 데이터가 자동 이관되지는 않습니다.

저장 공간 부족·손상 데이터·미지원 버전·Web Locks 미지원/시간초과·표시 실패의 강제 주입은 개발 fixture 및 기존 자동/브라우저 증거로 별도 관리합니다. **개발 fixture는 빌드 HTTPS 서버에서 제공되지 않습니다.** 휴대폰에서 fixture URL을 열거나 실제 저장 데이터를 손상시켜 재현하지 않습니다. 자연 발생한 오류는 기대값과 실제 동작을 결과표에 남깁니다. 기존 증거와 한계는 [Story 1.7 수용 보고서](../_bmad-output/implementation-artifacts/story-1-7-acceptance.md)를 참고합니다.

공개 호스팅 선택·공개 HTTPS/고정 origin·로그 정책·구버전 탭 종료 및 이관·v2 호환 롤백 리허설은 별도 미완료 항목입니다. 이 LAN 테스트 준비나 실기기 결과만으로 공개 배포 준비 완료를 선언하지 않습니다.
